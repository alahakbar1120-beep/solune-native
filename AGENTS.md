# Задание для ИИ-сборщика

Цель: собрать реально устанавливаемый debug APK Solune Native 2.1 для Motorola Moto G55 5G (ARM64, Android 16), используя исходники этой папки. Не переписывать интерфейс с нуля. Это непроверенный инженерный прототип, а не готовая сборка.

## Порядок работы
1. Изучить README.md, Gradle, AndroidManifest, MainActivity, EngineService, native.cpp и assets/index.html. Проверить установленное окружение: JDK 17, Android SDK 35, NDK 27.2.12479018, CMake 3.22.1, Gradle 8.9. При отсутствии установить официальные зависимости с согласия пользователя. Сгенерировать Gradle wrapper, если его нет. Не добавлять API-ключи.
2. Проверить совместимость Android Gradle Plugin и закреплённой версии llama.cpp b5046. Запустить `gradle :app:assembleDebug` (или `./gradlew :app:assembleDebug` после создания wrapper). Исправить реальные ошибки компиляции и повторять сборку до успешного результата. Не обходить системные ограничения среды.
3. Проверить ссылки GGUF по репозиториям, имена файлов и лицензии. Модели скачиваются после подтверждения пользователем, не входят в APK. Paper 1.2 — SmolLM2-360M-Instruct, Marble 1.5 — Qwen2.5-0.5B-Instruct, Opal 2.1 — Qwen2.5-Coder-1.5B-Instruct. Названия Solune — профили ассистента, не новые обученные веса. Сохранить честную атрибуцию в разделе «О приложении».
4. Проверить шаблон чата для каждой модели (предпочтительно использовать chat template из GGUF через llama.cpp вместо жёстко заданного ChatML), границы контекста, обработку UTF-8, остановку, ошибки JNI, сериализацию загрузки/генерации, сбои сети и памяти. Проверить взаимодействие WebView и сервиса, включая повторное открытие приложения и завершение сервиса. Не исполнять сгенерированный HTML с доступом к нативному мосту.
5. Проверить фон: foreground service с уведомлением, разрешения Android, WakeLock с ограничением времени, отмена, возврат в приложение. Не обещать работу после принудительного завершения процесса. Проверить требования target SDK к типу сервиса. На телефоне проверить отступы под вырез, клавиатуру, светлую/тёмную тему, отсутствие отправки пустых сообщений, меню, тарифы, лимиты, скиллы, SVG и изолированный предпросмотр кода.
6. Если доступен телефон/ADB, выполнить короткие реальные запросы на русском по каждой модели, измерить время до первого токена и токены/с, проверить потребление памяти и сворачивание во время ответа. При нехватке RAM уменьшить контекст и число потоков; не утверждать поддержку Opal без проверки. Если телефона нет, отдельно указать это ограничение.
7. Выдать APK из `app/build/outputs/apk/debug/app-debug.apk`, проверить наличие arm64-v8a/libsolune.so и подпись APK (apksigner verify), предоставить исправленные исходники, список выполненных тестов и оставшихся проблем. Не выдавать неподтверждённую компиляцию за успешную.

## Требования к продукту
Сохранить минималистичный интерфейс Solune, полумесяц, плавные панели, ручной выбор моделей, /img (SVG), /code, /deep, /instant, тарифы Free/Pro/Dev, бесплатное тестовое переключение тарифов, использование лимитов. Opal доступна Pro/Dev. Paper для быстрых запросов, Marble универсальна. Русский по умолчанию. Не подменять реальные ответы скрытыми шаблонами.
